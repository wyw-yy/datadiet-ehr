# 与提案（No.65 DataDiet-EHR）的逐条对照

> 口径：训练池 **48,000 条**，30% = **14,400 条**；近重复去重保留 **46,714 / 48,000 = 97.32%**。

## 五条必须写进 limitation 的偏离

1. **数据不是院内 EMR。** 用的是公开医学题库；没有结构化检验值、没有真实病历书写风格。这是最硬的一条。
2. **只做选择题，没做生成。** 评测是"读 A/B/C/D 的 logprob 取最大"，不是自由文本生成——它便宜、确定，但比真实临床问答窄得多。
3. **"优于随机"没成立。** 6 个种子方向翻转（MedQA +1.10 / −0.47 / +0.39 / +1.10 / +1.34 / −0.71），均值 +0.46pp，Stouffer p=0.166。论文只能写"无可检测优势"。
4. **长度混杂（仍存在，已量化）。** 24k 池上 nait 选中的样本比其余样本文本长 38.8%（12k 轮是 12.3%），所以同样 14,400 条，nait 的训练墙钟多 16%。长度匹配对照臂 `rand_len` 已跑完（分布差 ≤2%）：它与朴素随机打平（medmcqa −0.06、medqa −0.29，均不显著），说明长度既不是 nait 的优势来源，也不是它的劣势来源。
   **需要撤回的一条**：12k 轮曾报告"长度对齐后 nait 在 MedQA 上仍领先 1.13pp（6/6 同号，p=-0.101）"，24k 池上没有复现（+0.29，p=0.57，符号翻转）。按预注册判据作废，正文不得引用。
5. **种子数不足（已解决）。** 补到 6 个种子后，30% 档 8 个格子里 7 个种子口径等效；唯一失守的是 `nait_dedup` 在 MedQA 的 3 种子（−0.63pp，CI [−1.78, +0.52]）。
