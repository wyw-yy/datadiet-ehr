# 生成式评估设计（还没实现，先定方案）

> 现状：`eval.py` 只做**单选题**——算模型在 ` A/B/C/D` 四个 token 上的 logprob 并取最大，
> 不做文字生成。这快、确定、可复现，但回答不了"模型写出来的话临床能不能用"。
>
> 这份文档定下第二套评估的口径，等主表稳定后实现（`eval.py --mode gen`）。

## 1. 为什么需要它

选择题只测"认出正确答案"，临床关心的是"生成可用的回答"。两个具体缺口：

- **格式**：选择题是四选一，模型从不需要组织语言；住院记录总结、出院指导都需要。
- **幻觉**：模型可以靠蒙对选项，但生成时会编药名、编剂量，选择题测不出来。

## 2. 测什么（四个指标，缺一不可）

| 指标 | 定义 | 怎么算 | 谁来判断 |
|---|---|---|---|
| **答案准确率** | 自由作答里是否包含正确选项的语义 | 正则抽 `A/B/C/D` + 与标准答案比对；抽不到算错 | 自动 |
| **格式合规率** | 是否按指令输出（比如"先给答案字母，再给两句话理由"） | 正则匹配指令要求的结构 | 自动 |
| **临床安全性** | 是否出现危险建议（错剂量、禁忌药、延误就医） | 三段式：规则过滤 → 小模型打分 → 人工抽检 100 条 | 半自动 |
| **长度与可读性** | 回答长度、句数、术语密度 | 直接统计 | 自动 |

安全性那栏必须有人看：先用规则抓"毫克/片/每日 X 次"这类模式，再人工抽检。**不要全自动**。

## 3. 怎么评（协议）

```text
输入：同一批 500 道 MedMCQA 题（固定 seed 抽样，存 data/processed/gen_eval.jsonl）
模型：与主表完全相同的 adapter（full / nait@30 / random@30 / rand_len@30），不重训
解码：greedy（temperature=0），max_new_tokens=160，同一 chat template
输出：results/gen/<exp_id>_<task>.jsonl（每题一行：prompt, output, extracted, correct）
判定：上面的四个指标，逐题落表 → R 侧出 CI
```

固定 500 题、greedy 解码，是为了让"模型差异"不被采样噪声淹没；如果要报多样性，另开 temperature=0.7 的一组，但**不进主表**。

## 4. 成本

| 项 | 估算 |
|---|---|
| 每题生成 160 token，500 题 | 80k token / adapter |
| 1.5B 模型解码速度（实测约 40–60 tok/s） | 25–35 分钟 / adapter |
| 4 个 adapter × 2 任务 | 约 4 小时 |

可以只跑 full / nait / random 三个（rand_len 可选），压到 3 小时。

## 5. 已知风险与对策

| 风险 | 对策 |
|---|---|
| 用另一个模型当裁判会有偏好 | 裁判只用于"安全性"这一项，且与人工抽检 100 条比对，报告一致率（Cohen's kappa）；准确率一律用正则+标准答案，不用裁判 |
| 生成式指标方差大 | 500 题固定 + greedy；CI 用逐题 bootstrap，与主表同口径 |
| 指令格式影响分数 | 评测 prompt 全项目统一，写进 `docs/PROTOCOL.md` 的输入契约 |
| 生成太慢拖时间 | 先跑 100 题做 smoke，确认 20 分钟内出结果再上 500 |
