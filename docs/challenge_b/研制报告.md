# DataDiet-EHR：临床文本训练的数据冗余度评估与训练子集选择软件

**研制（究）报告**

参赛类别：科技发明制作 B 类
作品形态：软件系统（含可复现协议文档、审计工具链）
关键词：数据裁剪、神经元激活、训练子集选择、等效性检验、临床文本、算力预算

---

## 一、作品概述

本作品是一套**能直接跑的软件**，用来回答一个具体问题：**临床文本模型训练时，能不能少用一大半数据，还把效果保持住？**

它由三部分组成：

1. **Python 侧（23 个模块，约 3,500 行）**：数据清洗与切分 → 神经元激活采集 → 训练子集选择 → LoRA 微调 → 逐题评测 → 结果入账，一条命令跑完一个实验单元（`run_one.py`）。
2. **R 侧（8 个脚本，base R 零第三方依赖）**：逐题配对检验、自助法置信区间、等效性检验（TOST）、跨种子合并、Holm 多重比较、以及全部论文图表的生成。
3. **审计与调度层**：选择日志（每次挑选都留哈希与统计量）、产物哈希清单、断言式体检脚本（75 项）、夜间队列与断点续跑。

软件不追求"更大的模型"，而是把"**用多少数据才够**"变成可测量、可复现、可审计的一件事。

**主要技术指标（48,000 条训练池，保留 30%）**：

| 指标 | 结果 |
|---|---|
| 主任务（MedMCQA 4,183 题）掉点 | **−0.98 pp**，95% CI [−1.43, +0.22]，落在 ±2pp 等效界内 |
| 同规模随机抽样对照 | −1.40 pp，CI [−2.15, −0.86]，**下界越界** |
| 与随机对照的差值 | +0.50 pp（Stouffer p = 0.016，Holm 校正后 0.176，未达显著） |
| 端到端算力（含选择开销） | 2.128 → **1.093 GPU-h**，净省 **48.6%** |
| 评测可复现性 | 逐题预测 46 份、产物哈希 60+ 条、数字可溯源 100% |

## 二、研制目的与意义

### 2.1 临床 AI 的真实瓶颈是训练预算，不是模型结构

医院信息科或模型团队要微调一个临床文本模型（病历摘要、出院小结、编码辅助），成本主要由三块构成：数据标注与脱敏、GPU 训练时长、以及反复试错的迭代次数。其中**训练时长与数据量近似线性**：48,000 条样本、3B 级模型、单卡笔记本，一个 epoch 就要 0.639 GPU·小时；真实院内语料动辄十万到百万条，一次全量训练就是数天。

### 2.2 冗余是真实存在的，但没人量化

医患问答、出院小结这类文本有极强的模板与复述特征：同一个"胸痛待查"的问法会有几十个变体，同一位病人的多次入院记录高度重叠。我们的实测：48,000 条池子里，**语义近重复（余弦 > 0.95，去均值后）只占 2.68%**，但**文本长度、引用格式、章节结构**的高度同质让"随机抽样"也能拿到接近全量的效果——这正是很多团队"感觉砍一半也没事"的来源。

问题在于：**"感觉没事"不是证据**。要写进科室预算、要通过伦理与质量审查，需要的是带置信区间的等效性结论。

### 2.3 现有方法有三个缺口

1. **协议不可复现**：多数数据裁剪论文只给方法、不给可执行流程；换个数据集、换个人实现，结论就变。
2. **对照缺失**：只报"我们的方法比基线好"，不报"随机抽样能做到多少"。而随机抽样恰恰是最便宜的基线。
3. **算力账不诚实**：把"训练省了 70%"当成结论，却不扣"挑数据本身要跑一遍模型"的开销。我们实测：基于激活的选择只要 0.455 GPU·小时，基于全词表概率的 EL2N 要 0.512 GPU·小时——两者都要给整个池子跑一次前向，所以净收益只差 2.7 个点（48.6% 对 45.9%），而不再是论文里常写的"省 70%"。

本作品的目标就是补这三个缺口：**给协议、给对照、给净账。**

## 三、当前国内外同类研究水平概述

| 方向 | 代表工作 | 做法 | 与我们的差异 |
|---|---|---|---|
| 神经元激活选择 | *Neuron-Aware Data Selection in Instruction Tuning*（Nait，ICLR 2026） | 用目标域数据的激活模式做特征，按相似度选样本 | 我们**复现其机制**并接入临床文本流水线；不声称与官方实现对比（官方暂无可运行代码） |
| 难度/影响函数 | EL2N、GraNd（Paul et al., 2021） | 用早期训练误差/梯度范数给样本打分，剪掉"简单样本" | 我们把它做成**对照臂**，并如实报告它在本任务上**输给随机**、且**不省钱** |
| 梯度相似度 | LESS（Xia et al., 2024） | 用低维梯度特征做可迁移选择 | 需额外参考训练与梯度存储，8GB 笔记本不可行，列为后续 |
| 语义去重 | SemDeDup（Abbas et al., 2023） | 嵌入聚类去重 | 我们把它并入协议第一步（去均值后阈值 0.95） |
| 单义神经元解耦 | *Task-Specific Data Selection via Monosemantic Neuronal Activations*（NeurIPS 2025） | 指出原始激活存在"多义神经元"造成的伪相似，用 SAE 解耦后再算相似度 | 我们独立遇到同一现象（不去均值时 0.95 阈值把 85% 判成重复），用**均值校正 + 90 分位二值化**解决，未上 SAE——这是更轻的替代，也是我们与它的差异点 |
| 医学推理数据选择 | DIQ（CVPR 2026） | 医学 VLM 上用"难度 × 梯度"四象限选样本，报告 1% 追平全量、10% 超基线 | 我们在**纯文本 MCQ** 上做了同方向的极小预算档（1%/5%），结论相反：1% 两侧都掉 2.2–2.3pp；说明"能砍多狠"强依赖任务与模态 |
| 医学问答扰动选择 | RSP（arXiv:2610.33440） | 在医学 QA 上用扰动一致性选样本，预算 64/128/256 条，比熵匹配随机高 2.4–3.2 Macro-F1 | 我们做的是 480/2,400/14,400 条的量级与等效性检验，且给出 19 个随机子集的零分布作为参照 |
| 数据裁剪综述 | Data Pruning 综述（Joshi et al.） | 系统梳理"剪枝 vs 选子集" | 我们的差异在**等效性统计口径**与**净算力核算** |
| 临床语料 | MIMIC-III/IV、MedQA、MedMCQA | 公开临床文本与考题 | 我们用公开题库做主实验，院内 EMR 作为限制写明（见第八节） |

**水平判断（如实）**：在"数据裁剪"这个方向上，方法层面的新颖性属于中上（激活特征 + 分层配额），但我们真正的贡献在**工程与统计**：把一整条链路做到可复现、把对照做全、把算力账算净。这三件事在同类工作中普遍缺失，也正是能落地的部分。

## 四、研制过程

### 4.1 总体架构

作品是六段流水线（图 1，见附件）：

```
训练池 → 激活采集 → 选择协议 → LoRA 训练 → 评测 → 统计
                                  ↘ 随机对照 / 长度匹配对照 / EL2N 基线
```

每一段的输入输出都是**文件契约**（JSONL / NPZ / CSV / JSON），不靠内存传递，因此任何一段都能单独替换、单独复跑、单独审计。

### 4.2 数据层

- **训练池**：MedMCQA 训练集（182,822 条，含 21 个科室标签），按固定种子打乱后取 48,000 条作训练池、2,000 条作选择用探针集（probe）。
- **评测集**：MedMCQA 测试+验证集 10,333 条中筛出 4,183 条有合法答案的题（同域主任务）；MedQA（USMLE Step 1）1,273 题（跨任务迁移）。
- **防泄漏**：训练/探针/评测三者的题干做重叠检查，实测重叠 0 / 1 / 6 条（-0.10% / 0.02% / 0.03%），并写进数据卡。
- **清洗**：精确去重后保留率 97.32%（46,714 / 48,000）。

### 4.3 激活采集（本作品的核心工程之一）

- 取模型第 8、12、16、20、24 层的隐藏态；
- **只对回答（response）的 token 取平均**，避免题干模板把信号稀释；
- 采集时使用基座模型（不做前向训练），48,000 条耗时 25.7 分钟；
- **关键技术点：去均值（anisotropy 校正）**。大模型隐藏态方向高度集中，原始余弦相似度普遍在 0.95 以上，直接用阈值去重会误删 85% 的样本（我们第一版就踩了这个坑：当时池子 12,000 条，删到只剩 1,811 条）。减去池内每层均值后再归一化，随机样本对的余弦中位数从 0.95 降到 −0.01，阈值才恢复判别力。

### 4.4 选择协议

三段式，全部参数写进协议文档：

1. **语义去重**：去均值后余弦 > 0.95 视为重复，保留首次出现的样本；
2. **分层配额**：按科室占比分配名额（保证小科室不被整体剪掉）；
3. **簇内取分**：每候选用"与探针集激活中心的余弦"打分，按分数降序取满。

**消融结论（重要）**：把第 2 步去掉、直接取全局前 30%，结果没有变化（MedMCQA −0.89 vs −0.98，逐题配对 p > 0.4）。因此**分层配额在本任务上可省**，协议可以简化——我们把这条写进了报告，而不是藏起来。

### 4.5 训练

- 基座：Qwen2.5-1.5B-Instruct（15 亿参数，bf16 约 3.1 GB）；
- 微调：LoRA，r=16、α=32、dropout 0.05，作用于全部 7 个线性投影，可训练参数 **18,464,768 / 1,562,179,072 = 1.18%**；
- 上下文 512（实测 98.4% 样本 ≤512）、批大小 4 × 梯度累积 2、学习率 1e-4 OneCycle、1 epoch；
- **只对回答算损失**，指令部分 mask 掉。

### 4.6 评测

- **选项判别**：单次前向取最后一个位置的 logits，比较 `" A"`…`" D"` 四个 token 的 log 概率，不生成文本，快且确定；
- **生成式**：贪心解码 160 token，解析答案字母，同时统计格式合规率与四条红旗（擅自停药/超量用药/劝阻就医/武断诊断）；
- 每条题都落盘 `item_id, dept, pred, correct, pA..pD`，后续统计全部基于逐题预测，**不允许手抄汇总数字**。

### 4.7 统计口径（本作品与同类工作的最大差异）

| 环节 | 做法 | 为什么 |
|---|---|---|
| 单次比较 | 逐题配对 + 精确 McNemar | 同一批题被两个模型答过，只有"答得不一致"的题携带信息 |
| 置信区间 | 逐题 bootstrap 2,000 次 | 不假设正态；同时给"种子级"CI（把种子当抽样单位） |
| 等效性 | TOST，δ = 2pp | 先定界再跑，避免"跑完挑指标"；δ 由功效分析定（逐题差方差约 0.37，1,273 题 × 6 种子的 CI 半宽约 1.1–1.3pp） |
| 跨种子 | Stouffer 合并，**禁止把 3×4183 当独立样本合并** | 会低估方差、虚高显著性（我们第一版就犯过，已改正并写进协议） |
| 多重比较 | Holm 校正，按"主终点/方法对比/其余比例"划分家族 | 主终点不校正，探索性对比必须校正 |

### 4.8 工程实现（在 8 GB 笔记本上跑完 100+ 个训练）

这是作品能落地的前提，也是最花时间的部分：

- **显存**：3B 模型（权重 6.19 GB）在本机不可训（实测峰值 7.30–9.47 GiB > 8.15 GiB），改用 1.5B；给出三条替代路径（借 ≥12 GB 机器 / 租 4090 / QLoRA 4-bit）。
- **供电**：笔记本未插电时功率上限 40 W，GPU 只有 202 MHz、吞吐掉 3–10 倍。软件在训练日志里打印峰值显存，配合 `powercfg` 检查清单，避免"跑了一夜其实在爬"。
- **夜间队列**：`night_queue.py` 按 (方法, 保留率, 种子) 排队，跳过已完成项，单条失败不阻塞；每个 run 独立日志。
- **断点恢复**：adapter 与逐题预测按 `exp_id` 命名，重启后自动跳过；实测断电两次、崩溃三次，无数据损坏。
- **审计链**：每次选择写 `selection_log.jsonl`（含输入激活哈希、子集哈希、去重保留率、科室分布）；产物写 `ARTIFACTS.sha256`；`verify.py` 75 项断言、`audit_final.py` 六段交叉核对（含"文档里的每个数字能否在 CSV 里找到"）。

## 五、试验结果

### 5.1 主终点：30% 保留率下保持等效

48,000 条池、保留 30%（14,400 条）、6 个随机种子、δ = 2pp：

| 任务 | 方法 | 全量 | 30% | 掉点 | 逐题 95% CI | 逐题等效 | 种子等效 |
|---|---|---|---|---|---|---|---|
| MedMCQA | **本作品（激活选择）** | 0.4598 | 0.4545 | **−0.98 pp** | [−1.43, +0.22] | ✅ | ✅ |
| MedMCQA | 随机抽样 | 0.4598 | 0.4551 | −1.40 pp | [−2.15, −0.86] | ❌ | ✅ |
| MedQA | 本作品 | 0.4809 | 0.4784 | +0.04 pp | [−2.52, +1.26] | ❌（样本少、CI 宽） | ✅ |
| MedQA | 随机抽样 | 0.4809 | 0.4781 | −0.24 pp | [−2.36, +1.18] | ❌（同上） | ✅ |

**结论一**：在 30% 保留率下，激活选择在 6 个种子上都保持等效（最坏单种子 −1.58pp，仍在界内）；随机抽样则在 6 个种子上都掉出边界。**"少用七成数据"这件事，需要选，不能随便抽。**

### 5.2 与随机对照的差值

MedMCQA 上：**+0.50 pp**，95% CI [−0.04, +1.03]，Stouffer p = 0.016，Holm 校正后 **0.176（未达显著）**。
但 6 个种子里有 1 个方向相反（−0.36pp），因此我们只主张"**方向有利于激活选择，但证据尚不够硬**"，不主张"稳定优于随机"。这条边界我们在正文、图表、答辩口径里统一写明。

### 5.3 算力净账（本作品主张"诚实核算"）

| 方法 | 训练 | 选择前向（一次性） | 合计 | 相对全量净省 |
|---|---|---|---|---|
| 全量 48k | 2.128 | — | 2.128 GPU-h | 0 |
| 随机 30% | 0.639 | 0 | 0.639 | 70.0% |
| **本作品 30%** | 0.639 | **0.455** | **1.093** | **48.6%** |
| EL2N 30% | 0.639 | 0.512 | 1.150 | 45.9%（在 24k 轮实测） |

**结论二**：真正能兑现的是**约 48%**，不是"省 70%"。差的这 22 个百分点，就是"多看一遍模型"的代价——这是所有"数据裁剪省算力"宣传里被系统性忽略的一项。

### 5.4 消融与失败诊断（作品的一部分，而不只是附录）

| 实验 | 结果 | 说明 |
|---|---|---|
| 去掉分层配额 | −0.89 vs −0.98，p > 0.4 | 分层可省，协议可简化 |
| 长度匹配随机（rand_len） | −0.15（MedMCQA） | 长度不是机制：把长度分布对齐后，随机依然不如激活选择 |
| EL2N 基线 | −1.04 / −1.05；比随机差 0.80pp（Holm 0.025） | "挑最难的样本"在本任务上**输给随机**：所谓"难"多半是题干含糊或标注噪声 |
| 生成式评测（500 题） | 本作品 47.0% / 随机 49.4% / 全量 48.8% | 能力无差异；但本作品输出中位 68 token、引用样式出现率显著更高——**激活选择放大的是"文献腔"，不是能力** |

**结论三**：这条"失败诊断"是本作品最有价值的发现之一——它解释了为什么方法间差异这么小，也提醒使用者：**激活相似度筛的是文本装置（引用、页码、书名），不是题目价值。**

## 六、创新点

1. **把"能省多少数据"做成带置信区间的等效性结论**（TOST + 逐题配对 + 种子级 CI），而不是"我们的方法更好"。
2. **算力净账口径**：把选择前向开销计入，并**按方法分别实测**——同样的"30% 保留"，净省可以是 48% 也可以是 11%。
3. **各向异性校正后的激活选择**：去均值让去重阈值恢复判别力（本项目从"误删 85%"修正到"删 2.68%"）。
4. **可审计的流水线**：选择日志 + 产物哈希 + 75 项断言 + 文档数字溯源，任何人拿到仓库都能复跑并核对每个数字。
5. **诚实的负结果**：EL2N 输给随机、分层配额无贡献、激活选择放大风格而非能力——这些都在正文里，而不是删掉。

## 七、实际应用情况与应用前景

### 7.1 已具备的落地形态

- 一条命令完成"选数据 → 训练 → 评测 → 入账"，换数据集只需替换 `data/processed/` 下的四个 JSONL 并重跑三条命令，**代码零改动**；
- 已在院内场景的替身数据上端到端演练（合成出院小结 196 份，2.6 毫秒/份，含伪 ID、章节抽取、按病人切分、泄漏检查全部通过）；
- 软著登记材料已备（源程序 3,468 行、说明书 12 页），正在申请。

### 7.2 成本模型（可按医院规模外推）

| 场景 | 数据量 | 全量训练 | 本作品 30% | 净省 |
|---|---|---|---|---|
| 本次实验（1.5B，单卡笔记本） | 48k | 2.08 GPU-h（约 4 元） | 1.08 GPU-h | 48% |
| 院内中等规模（3B，A100） | 200k | 约 40 GPU-h（约 2,000 元） | 约 21 GPU-h | 约 48% |
| 多轮迭代（10 次实验） | 200k | 400 GPU-h | 210 GPU-h | 省约一半预算与一半等待时间 |

对信息科的意义：**同样的卡，能多跑一倍的迭代**；对模型团队的意义：**把"要不要减数据"从直觉变成可签字的技术结论**。

### 7.3 推广路径

1. **横向**：换语料（出院小结、影像报告、护理记录）不改代码，只需重跑数据准备与选择；
2. **纵向**：与院内模型训练流水线对接，把"选择 + 净账"作为训练前的标准步骤；
3. **对外**：协议文档 + 开源仓库（MIT 许可，数据不入库）可作为同类项目的起点。

## 八、存在不足与下一步工作

1. **数据不是院内电子病历**：主实验用公开题库（MedMCQA / MedQA），院内 EMR 需伦理批件与数据使用协议，尚未获得。已在数据卡与正文中作为限制写明，并给出 MIMIC-IV 的申请清单与"数据到手当天"执行手册。
2. **单 epoch、单基座**：1.5B + 1 epoch 是为了让 100+ 个 run 在单卡上可完成；3-epoch 轮已跑（2 种子），3B 因 8 GB 显存不可行，三条替代路径已写明。
3. **剂量-反应曲线不可识别**：10/20/50/70% 只有单种子，单点摆动能到 ±1.5pp，因此只对 30% 下结论，其余标注为探索性。
4. **评测偏"选择题 + 500 题生成式"**：真实临床价值需要专家评分与安全性评估，生成式评测的四条红旗只是粗筛。
5. **下一步**：真病历接入 → 跨基座（≥12 GB 卡）→ 3 epoch 六种子 → 专家评分。
