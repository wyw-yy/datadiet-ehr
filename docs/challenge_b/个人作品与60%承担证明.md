## 二、60% 怎么证明（最容易被质疑的一条）

不靠嘴说，靠可核查的记录。你现在的仓库就能直接出证据：

```bash
# 1) 谁提交的（全部提交都是你）
git log --format="%an" | sort | uniq -c
#   70 wyw-yy

# 2) 代码量
#   87 个源文件、10,982 行（*.py + tools/*.py + R/*.R）

# 3) 提交时间跨度（2026-10 ~ 2026-11，符合"2025-06-01 后完成"）
git log --format="%ad" --date=short | sort | sed -n '1p;$p'
```

建议在申报书"研制过程"里写一句可核验的话：

> 本人独立完成选题、协议设计、全部代码实现（87 个源文件、10,982 行）、全部实验执行（92 个 run）与论文/报告撰写；代码仓库提交记录 70 次全部由本人提交。两名合作者参与文献整理与图表校对，未参与核心算法与实验设计。

并把下面三样放进支撑材料：

1. `git log --format="%an %ad %s" --date=short` 的截图或 PDF（70 条）；
2. 软件著作权登记（你为第一著作权人，材料在 `softcopyright/`）；
3. 实验台账 `results/metrics_long.csv`（92 个 run 的 exp_id 都带方法/比例/种子）。

> 如果两名队友确实只做了校对类工作，**写清楚"未参与核心部分"比含糊更好**——评审最反感的是"挂名"，写清楚反而显得可信。

## 四、答辩时三句话（背下来）

1. **"30% 的数据，掉 0.96 个百分点，统计上落在 ±2pp 等效界内；随机子集掉 1.40pp，落在界外。"**
2. **"净省 48%，不是 70%——因为我把选择子集那一次前向也算进了成本，这是能兑现的数字。"**
3. **"我们没有做出比随机更好的选择器；我们做出的是第一个能判定'够不够等效'的协议，以及'冗余度才是省算力的真来源'这个结论。"**

第 3 句是加分项。评委见过太多"我们的方法更好"，没见过主动说"我们的方法没赢，但我们能证明该砍多少"。
