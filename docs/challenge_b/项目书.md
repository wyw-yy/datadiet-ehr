# 项目书

**项目名称**：DataDiet-EHR——面向临床语言模型的可复现训练子集选择与等效性评估

**作品类别**：科技发明制作（B 类，信息技术）

**申报形式**：个人作品

---

## 一、项目背景与必要性

医疗大模型在院内落地时，最贵的不是显卡，是数据。一份可用的临床训练语料要经过采集、脱敏、标注、伦理审查，周期以月计；而微调一次动辄数小时到数天 GPU 时间。于是"能不能少用一点数据"成了很实际的问题。

但行业里缺少判断依据。常见说法是"我们只用 10% 数据就达到基线"，可这类结论通常不报告三件事：等效是怎么判定的、随机删掉同样比例会怎样、选样本身要花多少算力。缺了这三项，读者无法区分"方法好"和"这批数据本来就冗余"。

本项目要做的不是再提出一个选样算法，而是把"少用多少数据还能等效"变成**可判定、可复现、可审计**的工程结论——并给出配套的开源实现。这在不同医院、不同科室的数据治理场景里都能直接套用。

## 二、项目目标与考核指标

| 目标 | 指标 | 当前达成 |
|---|---|---|
| 等效性判定 | 30% 保留率下 Δ 的 95% CI 落在 ±2pp | **达成**：nait −0.98 [−1.57, −0.07] |
| 随机对照 | 给出随机子集的零分布与通过率 | **达成**：19 个随机子集，37% 通过（MedMCQA） |
| 算力净账 | 选样前向计入后的净节省 | **达成**：48.6%（2.128 → 1.093 GPU-h） |
| 跨任务 | 第二个任务上给出同样口径的判定 | **达成**：MedQA 68% 通过，nait 位于第 53 百分位 |
| 可复现 | 一条命令重跑；文稿数字可回溯 | **达成**：三层审计（结构/数字/文稿）全绿 |
| 开源 | 协议 + 代码 + 结果 + 文档 | **达成**：MIT 许可，GitHub 仓库（private），v1.0.1 release |

考核口径全部写在 `docs/PREREG.md` 与 `docs/PREREG_NULLBAND.md`，分析前登记，不可事后更改。

## 三、研究内容与技术路线

技术路线是六段流水线，每段都有独立产物，可单独复核：

1. **数据准备**：把公开医患问答、MedQA、MedMCQA 统一成 JSONL（字段：id / dept / instruction / response），按科室打标签，做精确去重与近重复去重，按种子切分训练池与探针集。
2. **激活采集**：基座模型对池中每条样本前向一次，抽第 8/12/16/20/24 层在 response token 上的隐藏状态均值，落盘为 FP16 矩阵（48k × 5 × 1536）。
3. **子集选择**：均值校正 → 余弦相似度打分 → 0.95 阈值去重 → 科室分层配额 → 取前 k%。输出子集 ID 清单与选择日志。
4. **模型训练**：LoRA 微调（r16/α32，7 个投影层），只对 response 计算损失，bf16 + 梯度检查点，长度分桶以减少 padding。
5. **模型评测**：单次前向比较 A–D 四个选项 token 的对数概率，不生成文本；逐题落盘预测与四个选项概率，保证可复核。
6. **统计与核算**：逐题配对 bootstrap + 精确 McNemar + TOST；种子级区间；Holm 家族校正；算力按"训练 + 选样前向"结算。

配套一项**零分布**方法：同一保留率下跑 19–20 个随机子集，得到 Δ 的分布，把任何方法的收益表示为"落在第几百分位"而不是"比基线高多少"。这是本项目在方法学上的主要贡献。

## 四、创新点

1. **把等效性做成可判定口径**：预注册 δ = 2pp、逐题与逐种子双口径、Holm 家族固定，避免"跑完挑指标"。
2. **随机零分布替代单点对照**：报告"37% 的随机子集本来就能过"，而不是只跟一个随机种子比。
3. **算力净账**：把选样前向计入，nait 净省 48.6%（而非只报训练的 70%）；EL2N 因要在全池前向而只省 45.9%。
4. **协议可简化**：消融显示科室分层配额对结果无显著影响（p = 0.48–0.84），医院落地时可以去掉这一层。
5. **结论与任务耦合的机制解释**：同一套选择器在 MedMCQA 位于第 89 百分位、在 MedQA 退回第 53 百分位，说明"冗余底"由任务决定，不由算法决定。
